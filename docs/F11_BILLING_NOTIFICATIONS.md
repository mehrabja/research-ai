# F11 — Billing, usage, notifications and transactional email

Date: 2026-09-29
Branch: phase123-integration

## Scope

F11 connects the existing backend operational contracts to the production-facing frontend.

### Usage & billing

The `/usage-billing` route now reads live data from:

- `GET /api/v1/workspaces/{workspace_id}/usage`
- `GET /api/v1/workspaces/{workspace_id}/plan`
- `GET /api/v1/billing/plans`
- `GET /api/v1/billing/workspaces/{workspace_id}/subscription`

Owner actions are wired to the existing billing contract:

- plan changes
- Stripe checkout when configured
- cancel at period end
- resume subscription

No invoice totals or usage percentages are hard-coded in the UI. Invoice history is not rendered because the current backend does not expose an invoice endpoint.

### Notifications

The global notification button now reads the authenticated notification API and supports:

- unread count
- notification listing
- mark one as read
- mark all as read

The previous placeholder notification toast was removed.

### Transactional email landing flows

The frontend now contains:

- `/email-verify`
- `/password-reset`
- `/password-reset/confirm`

The login page links to the password-reset request flow.

These pages consume the existing auth endpoints and are compatible with verification/reset links generated by the transactional email provider.
